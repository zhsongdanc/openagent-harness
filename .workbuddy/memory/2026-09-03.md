## 修复 DeepSeek Responses API 报错 "reasoning_text must be passed back to the API"

- 现象：`ShellTest` 里模型首轮做出 tool call（pwd + tree）后，第二轮请求被 DeepSeek 拒绝，报 400。
- 根因：`DeepSeekResponseModel.convertInput` 生成的 input 里 `function_call` 与 `function_call_output` 交错排列（调用一个工具立刻写结果）。DeepSeek 要求同一轮内所有 `function_call` 连续排在一起、`function_call_output` 统一跟在其后，交错即触发该 400。
- 修复：`convertInput` 改为先缓存 `function_call_output`（ToolMessageItem），遇到非 function_call/output 的 item（reasoning/message/user/system）时再 flush，保证分组正确。抽出 `buildFunctionCall/buildFunctionOutput/buildReasoning/buildMessage` 四个私有方法。
- 验证：实测 DeepSeek 接口确认「交错=400、分组=200」；本地以 `-Dstore.engine=memory` 跑 `ShellTest` 通过，Agent 正常输出最终答案。
- 备注：项目 pom 目标 JDK 21，本机默认 `JAVA_HOME` 是 JDK8，编译/运行需切到 `/Users/demus/Library/Java/JavaVirtualMachines/ms-21.0.12.1/Contents/Home`。
